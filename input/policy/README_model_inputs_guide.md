# GCAM-China Model Input Requirements and Data Integration Guide

## Overview

This document describes the key input data requirements for running the
GCAM-China model, with a focus on integrating external carbon emission data
(such as Carbon Monitor) for scenario calibration and validation.

## Quick Start: Minimum Inputs for Running GCAM-China

To run a basic GCAM-China scenario, the following components are required:

| Category | Files | Location |
|----------|-------|----------|
| **Model time** | `modeltime.xml` | `input/gcamdata/xml/` |
| **Climate** | `hector.xml` | `input/gcamdata/xml/` |
| **Socioeconomics** | `socioeconomics_gSSP2.xml` | `input/gcamdata/xml/` |
| **Energy supply** | `resources.xml`, `en_supply.xml` | `input/gcamdata/xml/` |
| **Energy transformation** | `en_transformation.xml` | `input/gcamdata/xml/` |
| **Electricity** | `electricity.xml` | `input/gcamdata/xml/` |
| **Industry** | `other_industry.xml`, sector-specific files | `input/gcamdata/xml/` |
| **Buildings** | `building_det.xml` | `input/gcamdata/xml/` |
| **Transportation** | `transportation_UCD_CORE.xml` | `input/gcamdata/xml/` |
| **Agriculture/Land** | `ag_*.xml`, `land_input_*.xml` | `input/gcamdata/xml/` |
| **Emissions** | `all_energy_emissions.xml`, `Ccoef.xml` | `input/gcamdata/xml/` |
| **China provincial** | `*_CHINA.xml` files | `input/gcamdata/xml/` |
| **Solver** | `cal_broyden_config.xml` | `input/solution/` |
| **Policy** | Carbon cap/tax XML | `input/policy/` |

These XML files are generated by the `gcamdata` R package from underlying
CSV data files. The R data system (`input/gcamdata/`) must be run first.

## Carbon Emission Data Sources

### 1. CDIAC (Built-in, Historical)

The model's built-in historical CO2 data comes from CDIAC
(Carbon Dioxide Information Analysis Center):

- **File**: `input/gcamdata/inst/extdata/emissions/CDIAC_CO2_by_nation.csv`
- **Coverage**: 1949–2009 by country
- **Units**: kt C (kilotons of Carbon)
- **Sectors**: solids (coal), liquids (oil), gas, cement, gas flaring, shipping
- **Processing**: `input/gcamdata/R/zenergy_L100.CDIAC_downscale_ctry.R`

### 2. Carbon Monitor (External, Near-Real-Time)

Carbon Monitor provides near-real-time daily CO2 emission estimates
that can supplement or validate model outputs:

- **URL**: https://datas.carbonmonitor.org/API/downloadFullDataset.php?source=carbon_global
- **Coverage**: 2019–present, daily, by country
- **Units**: MtCO2/day
- **Sectors**: Power, Industry, Ground Transport, Residential,
  Domestic Aviation, International Aviation
- **Reference**: Liu et al. (2020), Nature Communications

#### Downloading Carbon Monitor Data

A download script is provided:

```bash
cd input/gcamdata/inst/extdata/emissions/
python fetch_carbon_monitor.py
```

This produces:
- `carbon_monitor_raw.csv` — Full raw dataset
- `carbon_monitor_China_annual.csv` — China annual totals by sector (MtCO2)
- `carbon_monitor_China_annual_MtC.csv` — China annual totals by sector (MtC)
- `carbon_monitor_global_annual.csv` — Global annual by country (MtCO2)

A reference data file is also included:
- `carbon_monitor_China_reference.csv` — Pre-computed China reference values

#### Unit Conversion

GCAM-China uses MtC (megatons of carbon) internally. Carbon Monitor data
is in MtCO2. Conversion: **MtC = MtCO2 × (12/44) ≈ MtCO2 × 0.2727**

| Year | Carbon Monitor (MtCO2) | In MtC | GCAM Scenario Cap (MtC) |
|------|------------------------|--------|-------------------------|
| 2019 | ~10,882 | ~2,968 | — (historical) |
| 2020 | ~10,663 | ~2,908 | — (historical) |
| 2021 | ~11,356 | ~3,097 | — (historical) |
| 2022 | ~10,947 | ~2,986 | — (historical) |
| 2023 | ~11,313 | ~3,085 | — (historical) |
| 2024 | ~11,116 | ~3,032 | — (historical) |
| 2025 | — | — | 3,350–3,400 (scenarios) |
| 2030 | — | — | 3,100–3,600 (scenarios) |

## Other Required Input Data Categories

### A. Socioeconomic Data

Required for all scenarios. Controls GDP growth, population, and
labor productivity assumptions.

| Data | Files | Source |
|------|-------|--------|
| GDP projections | `socioeconomics_gSSP*.xml` | SSP database |
| Population | `socioeconomics_CHINA.xml` | NBS, UN Population |
| Provincial GDP | `SSPS_GDP.csv` | SSP scenarios |
| Provincial population | `population_thous_province.csv` | NBS Census |

**Key**: Different SSP pathways (SSP1–SSP5) provide different socioeconomic
assumptions. The choice of SSP significantly affects emission projections.

### B. Energy System Data

## How to Generate XML Inputs from Data

The XML input files are generated by the `gcamdata` R package:

```bash
cd input/gcamdata

# Install R dependencies
Rscript -e "install.packages('devtools')"
Rscript -e "devtools::install_deps('.')"

# Generate all XML files
Rscript -e "devtools::load_all('.')" -e "driver(write_output=FALSE, write_xml=TRUE)"

# Or use the Makefile from the repository root
cd ../..
make xml
```

This reads all CSV data from `inst/extdata/` and produces XML files in
`input/gcamdata/xml/`.

## How to Run the Model

### Prerequisites

1. **Build the GCAM executable** (C++ model engine):
   ```bash
   cd cvs/objects/build/linux
   make
   ```

2. **Generate XML inputs** (R data system):
   ```bash
   cd input/gcamdata
   make xml
   ```

3. **Configure the scenario** (choose a configuration file):
   ```bash
   cd exe
   # Reference scenario
   ./gcam.exe -C configuration_china.xml

   # Carbon peak scenarios
   ./gcam.exe -C configuration_china_peak_early.xml
   ./gcam.exe -C configuration_china_peak_reference.xml
   ./gcam.exe -C configuration_china_peak_delayed.xml
   ```

### Configuration File Structure

Each `configuration_*.xml` specifies:

```xml
<Configuration>
  <Files>
    <!-- Model time definition -->
    <Value name="xmlInputFileName">../input/gcamdata/xml/modeltime.xml</Value>
    <!-- Climate target policy -->
    <Value name="policy-target-file">../input/policy/forcing_target_4p5.xml</Value>
    <!-- Output database location -->
    <Value name="xmldb-location">../output/database_basexdb</Value>
  </Files>
  <ScenarioComponents>
    <!-- ~60+ XML input components covering all model sectors -->
    <!-- Global components + China-specific provincial overlays -->
    <!-- Policy files (carbon cap/tax) -->
  </ScenarioComponents>
  <Strings>
    <Value name="scenarioName">Reference</Value>
  </Strings>
</Configuration>
```

## Integrating Carbon Monitor Data with Scenarios

### Use Case 1: Validate Scenario Projections

Compare GCAM-China model output (CO2 emissions) against Carbon Monitor
observed data to validate near-term emission trajectories:

```
Carbon Monitor 2024 China Total:  ~11,116 MtCO2 (~3,032 MtC)
Early Peak Scenario 2025 Cap:      3,350 MtC (12,286 MtCO2)
Reference Peak Scenario 2025 Cap:  3,400 MtC (12,469 MtCO2)
Delayed Peak Scenario 2025 Cap:    3,400 MtC (12,469 MtCO2)
```

### Use Case 2: Calibrate Near-Term Emissions

Carbon Monitor sector-level data can help calibrate the near-term (2020–2025)
emission trajectory by sector:

| Carbon Monitor Sector | GCAM Sector | 2024 MtCO2 | Share |
|----------------------|-------------|------------|-------|
| Power | electricity | ~5,397 | 48.6% |
| Industry | industry | ~3,685 | 33.2% |
| Ground Transport | transportation | ~1,355 | 12.2% |
| Residential | building | ~521 | 4.7% |
| Aviation (Dom+Int'l) | transportation | ~157 | 1.4% |

### Use Case 3: Construct Custom Scenarios

Use the observed trend to construct custom carbon cap trajectories.
Example for a "data-driven peak" scenario:

```python
# Observed total from Carbon Monitor (in MtC)
observed_2024 = 11116 * 12/44  # ~3032 MtC

# Project forward based on recent trend
# 2023→2024 change: -1.7%, suggesting plateau/decline
cap_2025 = 3032 * (1 + 0.005)  # slight increase: ~3047 MtC
cap_2030 = 3032 * (1 - 0.02) ** 6  # 2% annual decline: ~2682 MtC
```

## Data Freshness and Update Frequency

| Data Source | Update Frequency | Latest in Repo |
|-------------|-----------------|----------------|
| CDIAC | Historical (discontinued) | Through 2009 |
| CEDS | Annual updates | Through 2015 |
| Carbon Monitor | Near-real-time (daily) | Download as needed |
| China Statistical Yearbook | Annual | Through 2015 |
| SSP Scenarios | Fixed projections | SSP1–SSP5 |

**Recommendation**: Download fresh Carbon Monitor data before running new
scenarios to ensure the near-term calibration reflects the latest observations.
